GS MUSUMBA R186.73 — PERFORMANCE REALITY / DISTRICT DISCLOSURE

TARGET
- Immediate-feeling navigation on warm/returning sessions.
- No heavy workspace bundle blocking the first authenticated dashboard.
- Cached shell available quickly on weak mobile links after the first successful visit.
- Duplicate/inflight read protections from earlier production layers remain preserved.

IMPORTANT
- A universal cold-start <1 second guarantee on real 2G is physically impossible to certify from static code. 2G radio latency and throughput can exceed one second before the first server response.
- Username/staff-code/telephone first login requires identifier resolution before Supabase password authentication; registered-email login skips that resolver and is the fastest cold login path.
- Secure login still requires Supabase network authentication plus the role/bootstrap response. These security checks are intentionally not removed for benchmark speed.
- 33-user simultaneous operation requires a live load test against the actual Supabase database/plan. Static QA cannot certify concurrency.

R186.73 therefore optimizes the architecture without weakening authentication, RLS, write verification or audit behavior.
